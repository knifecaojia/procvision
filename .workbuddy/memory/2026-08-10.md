- 现象：git commit 提示 lock 存在，无法提交。
- 原因：`.git/index.lock`（14:33 残留）由上次中断的 git 操作留下，且无正在运行的 git 进程。
- 处理：`rm -f .git/index.lock` 删除后，`git status` 恢复正常，commit 阻塞解除。

## git 锁争用根因与最终修复（重要）
- 根因：本机同时运行 CodeBuddy(ZCode)、VS Code(Code.exe)、opencode、codex 等，其 Git 文件监视器会在 git 创建 `.git/index.lock` / `.git/HEAD.lock` 的瞬间抢开句柄；Windows 下被占用的文件无法被 git 重命名/删除，稳定报 `Invalid argument` / `File exists`。任何写索引或更新 HEAD 的 git 操作（add/commit/reset）都会被卡住。
- 关键技巧（绕过锁争用）：
  1. 把 `GIT_INDEX_FILE` 指向**仓库同盘(F:)且在 `.git` 之外**的临时文件（如 `F:/.../05ui-poc/.tmp_alt_index`），这样 git 写的是该文件的 `.lock`，监视器（只盯 `.git`）不会干扰。
  2. `git read-tree HEAD` 把正确树装入临时索引。
  3. `cp .tmp_alt_index .git/index` 同步回真实索引（cp 不走 git 锁机制，且监视器占的是 `.git/index.lock` 而非 `.git/index` 本身，可直接覆盖）。
  4. 每次 git 操作前先 `rm -f .git/index.lock .git/HEAD.lock` 清掉监视器留下的死锁。
  5. `/tmp`（= C:\Users\...\AppData\Local\Temp）不可靠：跨盘且临时索引文件在命令内会消失，不要用于此场景。
- 注意：用临时索引直接 `git commit` 时，要先 `git read-tree HEAD` 装入正确树，否则会误把 HEAD 全部文件判为"删除"（踩过坑：第一次用空临时索引导致误删 127 文件，已通过 `git update-ref HEAD <parent>` 回退修复）。
